`wow-forever.d.luau` is generated. A generator written in strict Luau and run by [Lune](https://lune-org.github.io/docs)
reads three pinned upstream sources and one small hand-written supplement, and writes the definitions together with
a coverage report.

```
Client dump (what exists) ──────┐
Blizzard API docs (types first) ┼─▶ generator/ ─▶ wow-forever.d.luau
LuaCATS annotations (the rest) ─┤                coverage.json, COVERAGE.md, report.json
supplements/ (FrameXML tables) ─┘
```

## The sources

| Source                                                                                                                                                                                     | Pinned in `upstream.toml` | Decides                                                                                                           |
| ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------- | ----------------------------------------------------------------------------------------------------------------- |
| [Ketho/BlizzardInterfaceResources](https://github.com/Ketho/BlizzardInterfaceResources/tree/forever), `forever` branch: dumps from the live Forever client                                 | `[resources]`             | **What exists**: every function, widget type and method, script handler, event and enum value                     |
| [Gethe/wow-ui-source](https://github.com/Gethe/wow-ui-source/tree/forever), `forever` branch: Blizzard's own `Blizzard_APIDocumentationGenerated`                                          | `[docs]`                  | **Types first**: arguments, results, nilability, structures, callback types, event payloads                       |
| [Ketho/vscode-wow-api](https://github.com/Ketho/vscode-wow-api) (MIT): the LuaCATS annotations behind the WoW VS Code extension, sourced from [warcraft.wiki.gg](https://warcraft.wiki.gg) | `[annotations]`           | **Types for the rest**: globals the documentation omits, FrameXML mixins, WoW's Lua extensions, extra call shapes |

Each source is pinned to a commit. An upstream change reaches the definitions only through a reviewed pull request
that bumps the commit and commits the regenerated output.

The fourth input, [`supplements/framexml.d.luau`](https://github.com/Braden1996/wow-forever-luau-types/blob/main/supplements/framexml.d.luau),
declares a few FrameXML tables and frames that addons use daily but no source types, such as `SlashCmdList`,
`UISpecialFrames` and `StaticPopupDialogs`. Every entry must exist in the client.

## Merge rules

The client dump is the filter. An annotated or documented API is emitted only if the Forever client has it; a
client API that no source types is emitted untyped, as `(...unknown) -> ...unknown`.

When Blizzard's documentation and the annotations both describe a function:

- **Types come from the documentation.**
- **An argument is optional if either source says so.**
- **The annotations' extra call shapes are kept** as additional overloads.
- **A documented result typed as a callback** (for example a timer handle) takes the annotation's type.

These rules live in `Signatures.reconcile` in `generator/stages/signatures.luau`; `generator/build.luau` runs the
stages. Data-only rules, such as which documented script object describes which widget, closed string unions and
parameter overrides, are in `generator/config.luau` and `generator/rules/`. Every rule
has a comment saying why, and a snapshot test.

## Derived types

The generator derives types rather than duplicating them:

- A family of structures that the client treats as one shares a base: the UI widget visualization infos are
  `UIWidgetVisualizationInfoBase & { extra }`. Structures that only happen to share fields are written out in full,
  so one never claims to be a kind of another.
- `CreateFrame` is generic over `FrameTypeMap`, so `CreateFrame("Button")` returns a `Button`.
- Each event handler type is a lookup into one payload table: `EventHandler<E> = index<EventPayloads, E>`.
- Every widget gets a union of its own script names, used by `SetScript`, `HookScript`, `GetScript` and `HasScript`.

These use `keyof` and `index` type functions, which is why the definitions need Luau's new type solver.

## Coverage

Every API the client has is recorded in `definitions/coverage.json` as **typed** (with its source), **untyped**, or
**excluded** (with the reason). [Coverage](/wow-forever-luau-types/coverage/) shows the totals and the full lists.

<Aside type="note" title="Coverage only grows">
  CI compares `coverage.json` with the base branch and fails if an API that was typed becomes untyped. An upstream bump
  that would lose types has to be fixed before it can merge.
</Aside>

## Checks

- `sgt check` covers formatting, lint, types, workflow audits, the generated artifacts, coverage regressions,
  samples, snapshots, and the addon template.
- `sgt test` runs converter specs and documentation tests.
- `sgt build` builds the site, including validation of Luau examples and internal links.


The negative fixtures in [`tests/fail`](https://github.com/Braden1996/wow-forever-luau-types/tree/main/tests/fail)
pin the strictness: each file must produce exactly the diagnostics in its `.expected` file, so a change that stops
reporting a misspelt event or a missing nil check fails CI.

## Releases

A release re-verifies the tagged commit from a cold start and publishes `wow-forever.d.luau`, `report.json`,
`coverage.json`, `COVERAGE.md` and `SHA256SUMS`. A minor version marks an upstream bump or any change that can break
existing code; a patch only removes false errors.
